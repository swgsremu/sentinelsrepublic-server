# SWGEmu Plugin System

This directory contains closed-source plugins that extend the game server functionality without modifying the open-source codebase.

## Plugin Architecture

The plugin system consists of:

1. **Plugin Interface** (in open-source MMOCoreORB):
   - `IPlugin` - Base plugin interface with lifecycle methods
   - `IEventListener` - Interface for receiving game events (chat, player actions, admin commands)
   - `ICommandHandler` - Interface for handling custom admin commands
   - `EventDispatcher` - Manages event distribution to plugins
   - `PluginLoader` - Loads and manages plugin lifecycle

2. **Closed-Source Plugins** (this directory):
   - `csr-monitor` - CSR monitoring plugin that logs game events to Redis

## Building Plugins

Each plugin has its own CMakeLists.txt. To build a plugin:

```bash
cd plugins/[plugin-name]
mkdir build
cd build
cmake ..
make
```

The compiled plugin (.so file) will be installed to `MMOCoreORB/bin/plugins/`.

## Plugin Configuration

Plugins are configured through the main server config file. Add these settings:

```
# Plugin system
Core3.PluginDirectory = "plugins"
Core3.EnablePlugins = true

# CSR Monitor plugin settings
CSRMonitor.LogChat = true
CSRMonitor.LogActions = true
CSRMonitor.LogCommands = true
CSRMonitor.BatchSize = 100
CSRMonitor.FlushInterval = 5000
CSRMonitor.RedisHost = "127.0.0.1"
CSRMonitor.RedisPort = 6379
```

## Creating New Plugins

To create a new plugin:

1. Create a new directory under `plugins/`
2. Implement the `IPlugin` interface and optionally `IEventListener` and/or `ICommandHandler`
3. Export the plugin factory functions:
   ```cpp
   extern "C" {
       IPlugin* createPlugin() {
           return new MyPlugin();
       }
       
       void destroyPlugin(IPlugin* plugin) {
           delete plugin;
       }
   }
   ```
4. Create a CMakeLists.txt to build your plugin as a shared library

## Plugin Dependencies

Plugins should minimize dependencies on game server internals. The plugin interface provides:
- Event data structures with all necessary information
- Logger for plugin output
- Access to configuration

Avoid including autogenerated headers or game object headers directly.

## Security

- Plugins run in the same process as the game server
- Only load trusted plugins
- Plugins have full access to server memory and resources
- Consider security implications when developing plugins
